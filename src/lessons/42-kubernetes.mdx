### Set up k3s and kubectl access \{.no-step\}

<details>
  <summary><strong>Click to expand: k3s + kubectl setup on Ubuntu Server</strong></summary>

  Check whether k3s is already installed:

  ```bash
  command -v k3s
  ```

  If this prints a path, **skip installation** and continue with kubeconfig setup below. Reuse your existing cluster; do not reinstall or change its runtime during this lab.

  If it prints nothing, install a single-node cluster with the default containerd runtime:

  ```bash
  sudo apt update
  curl -sfL https://get.k3s.io -o /tmp/install-k3s.sh
  sudo sh /tmp/install-k3s.sh
  ```

  The installer needs administrator privileges to create the system service. Docker remains your image build tool; k3s runs the Kubernetes workloads.

  Check the service:

  ```bash
  sudo systemctl status k3s --no-pager
  ```

  If it is inactive or failed, inspect its logs and ask for help before continuing. Do not rerun the installer as a troubleshooting step.

  ```bash
  sudo journalctl -u k3s -n 50 --no-pager
  ```

  Copy the cluster configuration into your own home directory. Run these commands as your normal VM user:

  ```bash
  mkdir -p "$HOME/.kube"
  sudo install -m 600 -o "$(id -u)" -g "$(id -g)" \
    /etc/rancher/k3s/k3s.yaml "$HOME/.kube/config"
  export KUBECONFIG="$HOME/.kube/config"

  # Persist once for future Bash sessions
  if ! grep -qxF 'export KUBECONFIG="$HOME/.kube/config"' "$HOME/.bashrc"; then
    echo 'export KUBECONFIG="$HOME/.kube/config"' >> "$HOME/.bashrc"
  fi
  ```

  This replaces the VM user's default kubeconfig with this course cluster's configuration. If you already use that file for another cluster, preserve it and ask for help first. Do not commit kubeconfig to Git.

  Use ordinary `kubectl`, **not `sudo kubectl`**. Setting `KUBECONFIG` explicitly ensures it uses your writable home-directory copy rather than the protected system file.

  Wait for the node to become Ready, then verify access:

  ```bash
  kubectl wait --for=condition=Ready node --all --timeout=120s
  kubectl get nodes -o wide
  kubectl get pods -A
  ```

  Continue only when your node is `Ready`. If the wait times out, inspect the service logs above and ask for help.
</details>

## Build and import your image for Kubernetes

In your Ubuntu VM terminal, return to the root of your own lab repository, then enter the existing application directory:

```bash
cd "$(git rev-parse --show-toplevel)"
git status
git branch --show-current
cd labs/20-containerized-node-app
ls app/package.json app/package-lock.json docker/Dockerfile
```

Build the image using the lab directory as its context:

```bash
docker build -t quote-app:local -f docker/Dockerfile .
```

**Import the image before deploying it.** Default k3s uses containerd, whose image store is separate from Docker's. A successful Docker build alone does not make the image available to Kubernetes.

```bash
docker save quote-app:local -o /tmp/quote-app.tar
sudo k3s ctr images import /tmp/quote-app.tar
sudo k3s ctr images list | grep 'quote-app:local'
```

Continue only when the image list contains `docker.io/library/quote-app:local`. All three operations must happen on the same Ubuntu VM that runs your single-node cluster.

If you change application code later, build and import a new tag, such as `quote-app:v2`, then update the Deployment's image to that tag. Applying unchanged YAML does not deploy a rebuilt image automatically.

<details>
  <summary><strong>Troubleshooting: image not found or cluster setup</strong></summary>

  For `ImagePullBackOff` or `ErrImagePull`, inspect the Pod's events with `kubectl describe pod <pod-name>`. Confirm that the Deployment image matches the imported tag exactly and that the import happened on this VM.

  After correcting an import for the existing tag, delete the failing Pod to let its Deployment create a replacement:

  ```bash
  kubectl delete pod <pod-name>
  kubectl get pods -w
  ```

  Press Ctrl+C to stop watching.

  If you are unsure whether the problem is your application image, try a public image:

  ```bash
  kubectl create deployment nginx-test --image=nginx
  kubectl rollout status deployment/nginx-test --timeout=120s
  ```

  If nginx becomes available, the cluster can run that public workload; investigate your application image and configuration. If it fails, inspect its events too: registry/network access may be the cause.

  Remove the diagnostic Deployment when finished:

  ```bash
  kubectl delete deployment nginx-test
  ```
</details>

## Create a Deployment

Create a file named `deployment.yaml` with the following content:

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: quote-app
spec:
  replicas: 1
  selector:
    matchLabels:
      app: quote-app
  template:
    metadata:
      labels:
        app: quote-app
    spec:
      containers:
        - name: quote-app
          image: quote-app:local
          imagePullPolicy: IfNotPresent
          ports:
            - containerPort: 3000
          readinessProbe:
            httpGet:
              path: /health
              port: 3000
            initialDelaySeconds: 3
            periodSeconds: 5
```

Apply it:

```bash
kubectl apply -f deployment.yaml
```

Observe:

```bash
kubectl get pods
kubectl describe pod <pod-name>
```

## Expose the application with a Service

Create `service.yaml`:

```yaml
apiVersion: v1
kind: Service
metadata:
  name: quote-app
spec:
  selector:
    app: quote-app
  ports:
    - port: 80
      targetPort: 3000
  type: ClusterIP
```

Apply it:

```bash
kubectl apply -f service.yaml
```

Verify:

```bash
kubectl get svc
```

Delete the running pod:

```bash

```

Observe:

```bash
kubectl get pods -w
```

Confirm:

- A new pod is created automatically
- The Service continues routing traffic
- Downtime is minimal

Observe:


- Three pods are running

## Introduce a controlled failure

This step is required for grading.

Modify your deployment to intentionally break readiness.

Examples:

- Change readinessProbe path to a non-existent endpoint
- Use the wrong container port
- Set an invalid image tag

Apply the change and observe:

```bash
kubectl apply -f deployment.yaml
kubectl get pods
kubectl describe pod <pod-name>
```

Confirm:

- Pods fail readiness
- Traffic is not routed
- Kubernetes reports the failure

Restore the correct configuration.
